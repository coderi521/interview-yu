我有看过 Vue 源码，之前在做商品管理后台的时候，遇到过一个必须读 keep-alive 源码才能完全搞清楚的问题。

我们用 `<keep-alive>` 缓存了路由组件，想保留列表页的查询条件和滚动位置，但是从详情页返回列表时，接口已经更新了，页面却不刷新。刚开始以为是我 watch 用得不对，后来发现是生命周期行为和我预期不一样。

我就去看了 Vue2 里 `keep-alive` 的源码，发现它是个抽象组件，内部有个 `cache` 对象会缓存子组件的 vnode 和实例。被缓存的组件不会真正销毁，第一次进列表会执行 `created/mounted`，以后再回来只会执行 `activated`，`destroyed` 也不会再触发。

结合这个实现，我最后把“拉列表数据”的逻辑从 `mounted` 挪到了 `activated`，再配合路由参数控制是否需要刷新，这样既保留了 keep-alive 的缓存优势，又能保证从详情回来时列表数据是最新的。

这个问题如果只看文档，知道有 activated 这个钩子，但不知道它背后的执行时机和缓存机制，很难设计出合理的刷新策略，所以我觉得这是一个典型的“需要看 Vue 源码才能彻底解决并解释清楚”的业务问题。

### 1. 业务背景（先讲业务，不要一上来就讲源码）

在公司做的后台管理系统里，有一套“商品管理”模块：

- 左侧是商品列表页 `ProductList`
- 点击一条商品会跳到详情页 `ProductDetail/:id`
- 为了优化体验，我们用 `<keep-alive>` 缓存了路由组件，保证：
    - 返回列表页时保留之前的查询条件、滚动条位置
    - 多次进出详情页不要重复请求太多接口

路由大概是这样：
```
<template>
  <keep-alive include="ProductList,ProductDetail">
    <router-view />
  </keep-alive>
</template>
```
### 2. 遇到的具体问题（说明这是个“文档不好查”的坑）

用户操作流程：

1. 在列表页搜索“商品A”，进入详情
2. 在详情页修改了商品状态（比如“下架”→“上架”）
3. 提交成功后点击“返回列表”

**现象：​**

- 列表页还是旧的状态，看起来像没更新
- 接口实际上已经返回了新数据，但页面不刷新
- 普通 `mounted`、`created` 里写的请求逻辑，只在第一次进入生效，再返回列表时根本不会再触发

简单说：**用了 `<keep-alive>` 后，页面状态被缓存了，但我们又希望列表在某些时机刷新，这个行为和预期不一致**。

网上搜只会告诉你“用 `activated` 钩子”，但在复杂场景下（动态路由 + 多个标签页 + include/exclude）单靠文档很难搞清楚**为什么 mounted 不触发、activated 什么时候触发、缓存到底存了什么**，于是就去看了 Vue 的源码。
### 3. 看 Vue 源码时重点看了什么

我主要看了两块源码（以 Vue2 为例，面试中你可以这么说）：

1. **内置组件 `keep-alive` 的实现**
    
    - 文件路径类似：`src/core/components/keep-alive.js`
    - 核心点：
        - `keep-alive` 是个**抽象组件**：自己不渲染 DOM，也不会出现在父子组件链中
        - 内部维护了一个 `cache` 对象，按组件的 key/name 缓存 vnode 和 `componentInstance`
        - 当再次渲染到同一个组件时，不会重新创建实例，只是把缓存的实例“激活”回来
    - 这就解释了为什么：
        - 第一次进入列表：会走 `created -> mounted`
        - 再次返回列表：不会再走 `created / mounted`，只会触发 `activated`
        - 对应地，离开时不是执行 `destroyed`，而是执行 `deactivated`
2. **组件生命周期与 keep-alive 的关系**
    
    - 在生命周期实现代码里（`lifecycle.js`），可以看到：
        - 被 `keep-alive` 包裹的组件**不会真正销毁实例**，只是在切换时挂起/激活
        - 因此 `beforeDestroy/destroyed` 钩子不会触发，而是用 `activated/deactivated` 替代部分职责

通过源码我确认了两件事：

- 业务上“返回列表不刷数据”不是 bug，而是 `keep-alive` 设计本身就**不会重新执行 mounted**；
- 如果想在“每次返回列表页时刷新数据”，就必须把刷新逻辑从 `mounted` 挪到 `activated`，或者根据路由参数/标记来决定是否刷新。
